## 1. 这条链路现在长什么样

```
参考图库分组（~/.petpet/refs/）
   │  ① 导入照片（首张自动当设定图，其余为姿势参考）
   ▼
Seedream 重绘（图片 API）→ 绿幕设定图（source = ai）
   │  ② 首帧闸门：四边绿色占比 ≥ 50% 才放行
   ▼
Seedance 生成动作视频（视频任务 API，ratio=1:1）
   │  ③ 建任务 → 轮询 → 下载 mp4
   ▼
~/.petpet/anim/<分组名>-<分组id尾6>/<action>-source.mp4
   │  ④ 隐藏窗口抽 12 帧 → 抠图 → 拼横向精灵表
   ▼
~/.petpet/anim/<...>/<action>-sheet.png
   │  ⑤ 装配：拷贝精灵表 + 写 pet.json（v3 契约）
   ▼
~/.petpet/pets/<id>/pet.json + <action>-sheet.png
   │  ⑥ 切换（托盘菜单 / 面板下拉）
   ▼
桌面宠物窗口（PixiJS 按列切帧播放）
```

**关键点：桌面上的「动图」不是 GIF、不是视频**，而是一张横向精灵表，运行时按 `new PIXI.Rectangle(col*cw, 0, cw, ch)` 切成 12 张纹理，用 `AnimatedSprite` 播放。所以「动得起来」完全取决于 12 帧之间是否真有差异。

## 2. 当天修掉的问题（按发现顺序）

### 2.1 模型 ID 少了日期后缀 ✅ 已验证

- 现象：重绘报 `404 InvalidEndpointOrModel.NotFound`
- 原因：代码写死 `doubao-seedream-5-0-pro`，标准端点上不存在
- 排查手段：`GET {base}/models`（带 Bearer）列出账号可见模型
- 结论（2026-11-03 实测可用）：

| 能力 | 正确 ID |
|---|---|
| 生图 pro | `doubao-seedream-5-0-pro-260628` |
| 生图 flash | `doubao-seedream-5-0-flash-260915` |
| 视频 | `doubao-seedance-2-0-260128` |
| 生图 4.0 | `doubao-seedream-4-0-20260415`（该账号未开通） |

- 处理：默认值改为带后缀写法；旧的无后缀写法在 `resolveModel` 里自动规范化；面板改为可手填模型 ID（含 `ep-` 接入点）

### 2.2 抽帧拿到的永远是同一帧 ✅ 已验证

- 现象：装配出的桌宠完全不动
- 证据：精灵表 12 帧像素差异 **0.0000**（样例素材是 0.0662）
- 原因：`petmedia://` 自定义协议返回的响应没有 Range 支持，`<video>` 退化为不可寻址
  ```
  视频信息: {"duration":5.088, "seekable":[[0,0]]}
  请求 0.3s / 2.5s / 4.6s → 实际 currentTime 全是 0，校验和完全相同
  ```
- 处理：先 `fetch` 成 Blob，再用 `URL.createObjectURL` 喂给 `<video>`（Blob 天然可寻址）
- 效果：帧间差异 0.0000 → **0.0515**

### 2.3 精灵表 12 帧被平移下移、下半截裁掉 ✅ 已验证

这是当天最重要的一个 bug。

```js
// 错：cellSize - (cellSize - h) 化简后就是 h
const dy = cellSize - Math.round(cellSize - h)
// 对：
const dy = cellSize - h
```

- 后果：每帧被画在 `y = h` 处，画布下端溢出格子被裁掉，屏幕上只剩一条 2:1 的横带
- 实测对比：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 格子内内容 | 451 × 199 | 451 × 320 |
| 内容宽高比 | 2.27 : 1 | **1.41 : 1** |
| 垂直利用率 | 39% | **62%** |
| 原始帧宽高比 | 1.40 : 1 | 1.41:1 ✅ 吻合 |

### 2.4 抠图：硬编码键色 → 自动拾取 → 色度平面判定 ✅ 已验证

演进过程（三次都踩了坑，最终方案是这样定下来的）：

1. **硬编码 `#00C800`**：模型实际出的绿是 `#00861E`，还带明暗渐变，暗处超容差 → 留下一大片绿
2. **自动拾取键色 + 放大容差到 220**：把深棕色的毛一起吃掉，抠出来只剩几道橙色条纹
3. **最终方案：色度平面判定**

```
dominance = (G - max(R,B)) / 255

绿背景 (0,134,30) → 0.41   ≥ 门槛 → 删
橘猫   (220,150,100) → -0.27 → 保留
深棕毛 (150,90,60)  → -0.60 → 保留
```

该值对明暗不敏感，因此天然免疫渐变与暗角。再叠加两条：
- 键色由四边中位色自动拾取（`borderColorStats`）
- 离键色很近的极暗绿也清掉（容差 = max(45, min(80, p75))）

### 2.5 裁剪框被 1px 边缘杂色撑到整帧 ✅ 已验证

- 证据（逐帧追踪）：

  ```
  帧 1  chroma  930×720  y=0
  帧 7  chroma 1012×720  x=0,y=0
  ```

  每一帧高度都等于整帧高 720，说明包围盒被画面边缘的残留像素撑满
- 处理：
  - `trimBounds` 改为**行列成片判定**（该行/列不透明像素 ≥ 0.4% 才计入）
  - 新增 `clearBorderRing(data, w, h, 2)`：最外 2 像素强制清零

### 2.6 画幅用 16:9 导致主体上下出血 ✅ 已验证

- 现象：猫的耳朵被切掉
- 证据（原始帧实测）：
  ```
  画面尺寸 1280 × 720（16:9）
  主体 bbox 987 × 720     y[0, 719]
  顶部贴边 = True，底部贴边 = True
  ```
- 原因：**图生视频继承首帧场景**，16:9 横画幅高度只有 720，模型为填满画面只能放大到出血；提示词压不过画幅
- 处理：`ratio` 由 `16:9` 改为 `1:1`
- 效果（新素材）：

  | 画幅 | 内容比例 | 垂直利用率 | 结果 |
  |---|---|---|---|
  | 1280×720 | 1.41:1 | 62% | 头顶贴边 |
  | 1280×720 + 定位 bug | 2.27:1 | 39% | 只剩横带 |
  | **960×960（1:1）** | **0.80:1** | **88%** | 耳朵四腿尾巴完整 |

### 2.7 自动抽帧必然失败（路径少了分组目录）✅ 根因已定位，修复待验证

- 现象：点「生成动画」后日志停在 `{"stage":"extract"}` 再无输出，而手动「重抽帧」永远正常
- 定位手段：加分段日志后一次命中

  ```
  [抽帧] 进入 runAnimatorExtract: C:\Users\Asdfg\.petpet\anim\idle-source.mp4（存在=false）
  [error] [动画] 生成流程异常: Error: 视频文件未就绪：...\anim\idle-source.mp4
  ```

- 原因：调用时只传了文件名，解析到 `anim\` 根目录；真实文件在 `anim\pet-58e5f3\` 下
  ```js
  await runAnimatorExtract(videoFile, ...)                    // ❌
  await runAnimatorExtract(`${slug}/${videoFile}`, ...)       // ✅
  ```
- 为什么手动重抽一直好的：它走的是另一条正确写法（`${path.basename(dir)}/${videoFile}`）
- 同时补的健壮性：
  - `anim:generate` 的 catch 补 `console.error`（此前静默吞异常，日志看起来就是「断掉」）
  - 隐藏窗口每步打日志（窗口已建 / 页面已加载 / buildFromVideo 已返回）
  - `executeJavaScript` 外层 90 秒硬超时
  - `seekTo` 单帧 8 秒超时，超时用当前帧继续并计数，一半以上失败则明确报错
  - 落盘后 `statSync` 校验字节数与下载量一致
  - 抽帧前等文件稳定（大小非 0 且两次 stat 一致）

### 2.8 装配打进旧素材 ✅ 已验证

- 现象：装配「成功」但桌宠没变化
- 证据：
  ```
  15:21:20  idle-sheet.png   ← 旧精灵表
  15:36:03  idle-source.mp4  ← 新视频
  15:36:45  装配 → 打进的是 15:21 那张
  ```
- 处理：装配前校验 `精灵表 mtime < 视频 mtime` 则拒绝，并在动画生成中（busy）也拒绝

## 3. 当前实际使用的提示词（原文）

### 3.1 视频（Seedance）

模板：

```
{风格}，{动作动词链}。主体全身完整入镜，头顶上方留出明显空白，四爪均不出画框，四周留出余白，
动作连贯成可循环的单一动作，背景为纯绿色 #00C800，无渐变、无阴影、无杂物，
地面无投影，主体下方不出现任何影子，摄像机完全静止，不推拉、不摇移、不俯仰、不升降
```

实际拼出（idle，风格取配置里的「皮克斯3D卡通风格」）：

```
皮克斯3D卡通风格，安静待机，偶尔眨眼，尾巴轻摇，呼吸平稳。主体全身完整入镜，头顶上方留出明显空白，
四爪均不出画框，四周留出余白，动作连贯成可循环的单一动作，背景为纯绿色 #00C800，无渐变、无阴影、无杂物，
地面无投影，主体下方不出现任何影子，摄像机完全静止，不推拉、不摇移、不俯仰、不升降
```

六种动作的动词链：待机 / 睡觉 / 撒娇 / 奔跑 / 伸懒腰（五阶段箭头序列）/ 露肚躺。

### 3.2 图片重绘（Seedream）

```
{风格}。保持{宠物名}的毛色与花纹不变，全身正面站立，纯绿色 #00C800 背景，无渐变无阴影，
柔和影棚光，全身完整入镜（含尾巴），画面稳定
```

两处提示词的绿色来自同一个常量 `animator.BG_HEX`（由 `CHROMA_KEY` 推导），避免以后写歪分叉。

### 3.3 措辞规矩

视频提示词**禁止出现** `不要 / 别 / 避免 / 禁止`，由单测强制。统一改成「无 X / 不出现 X」——否定词会让模型把注意力放在被否定的对象上。

## 4. 护栏（防止再花冤枉钱）

| 护栏 | 位置 | 行为 |
|---|---|---|
| 就绪度闸门 | 重绘 | 设定图 ≥1 且姿势参考 ≥3，否则不发请求 |
| **首帧绿幕闸门** | 生成动画 | 逐张算四边绿色占比，取第一张 ≥50% 的；一张都不达标直接拒绝并列出各图占比 |
| 纹理上限 | 拼表 | `帧数 × cell ≤ 16384`（WebGL 硬上限） |
| 陈旧素材闸门 | 装配 | 精灵表比视频旧 → 拒绝 |
| 并发闸门 | 装配 | 动画生成中 → 拒绝 |
| 路径边界 | 协议 | `isSafeUnderRoot` 校验 `petmedia://` 请求 |

首帧闸门的现实意义：一张灰底首帧会让整次视频生成（约 108,900 tokens）白花，而且事后无法补救——视频里根本没有绿幕可抠。

## 8. 已知未完成 / 未验证

1. **`anim:generate` 自动抽帧的路径修复尚未实跑验证** ⚠️

   ```

   [抽帧] 窗口已建，开始 loadFile
   [抽帧] 1/12 … 12/12 → buildFromVideo 已返回
   ```

2. **当前桌宠仍来自 16:9 那段素材** ⚠️
   耳朵在视频源头就被切了，改代码救不回来。960×960 的新素材已验证抠图与构图正常，但装配到桌面上的那只还需要再跑一次完整流程。

3. **正方形格子仍有约 12% 空白**
   内容 0.80:1 塞进 1:1 格子。改非方形格子只能减少文件体积与空白，**不改变屏幕上的大小**（`fit = min(W/fw, H/fh)` 按比例算），所以本轮未做。

4. **透明底只对静态图可行**
   Seedream 支持 `background: "transparent"`（要求 PNG 输出 + 恰好 1 张带 alpha 的 PNG 参考图），可让设定图直接透明；但 mp4 没有 alpha 通道，**动作素材必须抠图**，这条路绕不开。
